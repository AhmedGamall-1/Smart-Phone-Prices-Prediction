```python
def clean_missing_values(df):
    df_clean = df.copy()
    
    # For numerical columns: fill with median
    numerical_cols = df_clean.select_dtypes(include=[np.number]).columns
    for col in numerical_cols:
        median_val = df_clean[col].median()
        df_clean[col].fillna(median_val, inplace=True)
    
    # For categorical columns: fill with mode (most common value)
    categorical_cols = df_clean.select_dtypes(include=['object']).columns
    for col in categorical_cols:
        mode_val = df_clean[col].mode()
        df_clean[col].fillna(mode_val[0], inplace=True)
    
    return df_clean
```

EXPLANATION:

**Two Strategies Based on Data Type:**

**1. Numerical Features → Median Imputation**
- **Why Median instead of Mean?**
  * Median is the middle value when data is sorted.
  * It's robust to outliers (extreme values don't affect it).
  * Example: If phone prices are 100, 200, 300, 10000, mean = 2650 (skewed by 
    outlier), but median = 250 (more representative).
- **How it works:** Find the middle value of all non-missing values, fill 
  missing entries with this value.

**2. Categorical Features → Mode Imputation**
- **Why Mode?**
  * Mode is the most frequently occurring value.
  * For categories, there's no concept of "average" or "median".
  * The most common value is the safest assumption.
- **Example:** If most phones are from "Samsung", fill missing brand with 
  "Samsung".

**Why Not Delete Missing Values?**
- We would lose valuable data.
- Small datasets can't afford to lose rows.
- Imputation preserves data while handling incompleteness.

**Result:** 0 missing values after cleaning.

```python
def create_new_features(df):
    df_new = df.copy()
    
    # 1. Performance Score
    df_new['performance_score'] = (
        df_new['RAM Size GB'] * 0.3 + 
        df_new['Storage Size GB'] * 0.1 + 
        df_new['Clock_Speed_GHz'] * 10 * 0.6
    )
    
    # 2. Camera Score
    df_new['camera_score'] = (
        df_new['primary_rear_camera_mp'] * 0.7 + 
        df_new['primary_front_camera_mp'] * 0.3
    )
    
    # 3. Display Score
    df_new['display_score'] = (
        df_new['Screen_Size'] * 0.3 + 
        (df_new['Resolution_Width'] * df_new['Resolution_Height'] / 1000000) * 0.4 +
        (df_new['Refresh_Rate'] / 10) * 0.3
    )
    
    # 4. Battery Efficiency
    df_new['battery_efficiency'] = df_new['battery_capacity'] / df_new['Screen_Size']
    
    # 5. Premium Features Count
    df_new['premium_features_count'] = 0
    for feature in ['5G', 'NFC', 'IR_Blaster']:
        df_new['premium_features_count'] += (df_new[feature] == 'Yes').astype(int)
    
    # 6. Brand Premium Score
    brand_ratings = df_new.groupby('brand')['rating'].mean().to_dict()
    df_new['brand_premium_score'] = df_new['brand'].map(brand_ratings)
    
    return df_new
```

EXPLANATION:

**What is Feature Engineering?**
- Creating new features (columns) from existing ones.
- Combines related information into more meaningful signals.
- Often improves model performance significantly.

**The 6 New Features Created:**

**1. Performance Score** (Most Important - 14.71% importance)
```
performance_score = RAM × 0.3 + Storage × 0.1 + (Clock_Speed × 10) × 0.6
```
- **Why these weights?**
  * CPU speed (60%): Most important for overall phone performance.
  * RAM (30%): Affects multitasking and app performance.
  * Storage (10%): Affects capacity but not speed.
- **Purpose:** Creates a single metric representing computational power.

**2. Camera Score**
```
camera_score = Rear_Camera_MP × 0.7 + Front_Camera_MP × 0.3
```
- **Why these weights?**
  * Rear camera (70%): Primary camera for photos, videos.
  * Front camera (30%): Used for selfies, video calls.
- **Purpose:** Captures overall photography capability.

**3. Display Score**
```
display_score = Screen_Size × 0.3 + (Resolution / 1,000,000) × 0.4 + (Refresh_Rate / 10) × 0.3
```
- **Components:**
  * Screen size: Physical display area
  * Resolution: Pixel count (divided by 1M to normalize)
  * Refresh rate: Display smoothness (divided by 10 to normalize)
- **Purpose:** Measures visual experience quality.

**4. Battery Efficiency**
```
battery_efficiency = Battery_Capacity / Screen_Size
```
- **Logic:** mAh per inch of screen.
- **Purpose:** Larger screens need more battery. This normalizes capacity 
  relative to screen size.
- **Higher value = better efficiency.**

**5. Premium Features Count**
```
Count how many of: 5G, NFC, IR_Blaster the phone has
Range: 0-3
```
- **Purpose:** Quantifies "premium-ness" of the phone.
- **Insight:** More premium features → likely more expensive.

**6. Brand Premium Score**
```
Average rating of all phones from that brand
```
- **How it works:**
  * Group all phones by brand
  * Calculate average rating for each brand
  * Assign that average back to each phone
- **Purpose:** Captures brand reputation and quality perception.

**Result:** Dataset grows from 33 to 39 columns.

EXPLANATION:

**What is Scaling?**
- Transforms features to have similar ranges.
- StandardScaler makes each feature have mean=0 and std=1.

**Formula (Z-score normalization):**
```
z = (x - μ) / σ
```
Where:
- x = original value
- μ = mean of the feature
- σ = standard deviation

**Why is Scaling Important?**

**Problem without scaling:**
- RAM: ranges 1-18 GB
- Battery: ranges 1000-8000 mAh
- Rating: ranges 0-100

Models might think battery is more important just because its numbers are bigger!

**After scaling:**
All features have similar ranges (-3 to +3 typically), so they contribute equally.

**Why fit on train, transform both?**
- `fit_transform(X_train)`: Learns mean/std from training data only.
- `transform(X_test)`: Applies same transformation to test data.
- **Why?** Test data simulates "future" data. We can't peek at it during training!

Advanced boosting algorithm that builds trees sequentially.

Hyperparameters:

Linear model for binary classification.

Hyperparameters:

Finds optimal decision boundary between classes.

Hyperparameters:
- `C` [0.1, 1, 10]: Regularization parameter.

  RBF = handles non-linear patterns.
  Linear = simpler, faster.

**5. Gradient Boosting Classifier**
Builds trees sequentially to correct errors.

Hyperparameters:
- `n_estimators` [100, 200]: Number of boosting stages.
  
- `max_depth` [3, 5]: Maximum tree depth.

EXPLANATION:

**What is GridSearchCV?**
- "Grid Search" = Try all combinations of hyperparameters.
- "CV" = Cross-Validation to evaluate each combination.
- Finds the best hyperparameter combination automatically.

**What is StratifiedKFold?**
- Splits data into 5 folds.
- "Stratified" = Maintains class proportions in each fold.
- Since we have 72% non-expensive, each fold will also have ~72% non-expensive.
- `shuffle=True`: Randomizes data before splitting.
- `random_state=42`: Ensures reproducibility.

**How GridSearchCV Works:**

Example for Random Forest:
- n_estimators: 2 options [100, 200]
- max_depth: 3 options [10, 20, None]
- min_samples_split: 2 options [2, 5]
- Total combinations: 2 × 3 × 2 = 12 combinations

For each combination:
- Train on 4 folds, test on 1 fold
- Repeat 5 times (each fold is test once)
- Calculate average accuracy

Total models trained: 12 combinations × 5 folds = 60 Random Forest models!

**GridSearchCV Parameters:**
- `cv=cv`: Use our StratifiedKFold
- `scoring='accuracy'`: Optimize for accuracy
- `n_jobs=-1`: Use all CPU cores for parallel training
- `verbose=0`: Don't print too much output

- `predict_proba()`: Returns probability for each class [P(0), P(1)]
- `[:, 1]` takes probability of class 1 (non-expensive)

**Evaluation Metrics Explained:**

**1. Accuracy**
```
Accuracy = (Correct Predictions) / (Total Predictions)
```
- Simple and intuitive.
- Can be misleading with imbalanced data.

**2. Precision**
```
Precision = True Positives / (True Positives + False Positives)
```
- "Of all phones I predicted as expensive, how many are actually expensive?"
- Important when false positives are costly.

**3. Recall (Sensitivity)**
```
Recall = True Positives / (True Positives + False Negatives)
```
- "Of all actually expensive phones, how many did I find?"
- Important when missing positives is costly.

**4. F1-Score**
```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```
- Harmonic mean of precision and recall.
- Balances both metrics.
- Good when you want balance between precision and recall.

**5. AUC-ROC (Area Under ROC Curve)**
- Measures discrimination ability across all thresholds.
- Range: 0.5 (random guess) to 1.0 (perfect).
- Robust to class imbalance.
