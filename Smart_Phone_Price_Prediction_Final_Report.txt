================================================================================
                         1. INTRODUCTION
================================================================================

This project aims to develop a machine learning model that predicts whether a 
smartphone is "expensive" or "non-expensive" based on its technical 
specifications. The classification problem uses various smartphone features 
such as RAM, storage, processor speed, camera quality, and connectivity 
options to make accurate price category predictions.

Project Objectives:
• Build a robust binary classification model for smartphone pricing
• Analyze the relationship between phone specifications and price categories
• Compare multiple machine learning algorithms to find the best performer
• Deploy a production-ready model for real-world predictions

Dataset Overview:
• Training Dataset: 867 smartphones
• Test Dataset: 153 smartphones
• Total Features: 32 technical specifications
• Target Variable: Price category (expensive / non-expensive)
• Class Distribution: 71.9% non-expensive, 28.1% expensive

2.2 DUPLICATE REMOVAL
--------------------------------------------------------------------------------

During data inspection, 6 duplicate records were identified in the training 
dataset. These duplicates were removed to ensure data integrity and prevent 
any bias in model training.

Code Applied:
    total_duplicates = train_df.duplicated().sum()  # Found: 6
    train_df = train_df.drop_duplicates()

Rationale: Duplicate records can artificially inflate model performance and 
lead to overfitting, as the same data points may appear in both training 
and validation sets during cross-validation.


2.3 HANDLING MISSING VALUES
--------------------------------------------------------------------------------

A comprehensive missing value imputation strategy was implemented using two 
different approaches based on the data type:

A) Numerical Features - Median Imputation:
   • Strategy: Replace missing values with the median of each column
   • Features affected: rating, RAM Size GB, Storage Size GB, battery_capacity,
     Clock_Speed_GHz, Screen_Size, Resolution dimensions, camera specifications
   • Rationale: Median is robust to outliers and provides a better central 
     tendency estimate for skewed distributions compared to mean

B) Categorical Features - Mode Imputation:
   • Strategy: Replace missing values with the most frequent value (mode)
   • Features affected: brand, Processor_Brand, 5G, NFC, IR_Blaster, etc.
   • Rationale: For categorical data, the most common value is the safest 
     assumption when actual value is unknown

Code Applied:
    # For numerical columns
    for col in numerical_cols:
        median_val = df[col].median()
        df[col].fillna(median_val, inplace=True)
    
    # For categorical columns
    for col in categorical_cols:
        mode_val = df[col].mode()[0]
        df[col].fillna(mode_val, inplace=True)

Result: After imputation, the dataset contained 0 missing values.


2.4 FEATURE ENGINEERING
--------------------------------------------------------------------------------

Feature engineering is the process of creating new features from existing ones 
to improve model performance. Six new features were created based on domain 
knowledge about smartphone specifications:

**Feature 1: Performance Score**

Formula: performance_score = (RAM × 0.3) + (Storage × 0.1) + (Clock_Speed × 10 × 0.6)

This composite score combines three hardware specifications:
- RAM (30% weight): Affects multitasking and app performance
- Storage (10% weight): Affects capacity but less impact on performance
- Clock Speed (60% weight): Most important for computational speed

Rationale: Expensive phones typically have better overall hardware performance. 
This single metric captures the combined effect of multiple performance factors.


**Feature 2: Camera Score**

Formula: camera_score = (Rear_Camera_MP × 0.7) + (Front_Camera_MP × 0.3)

This score combines camera specifications:
- Rear Camera (70% weight): Primary camera used for photos and videos
- Front Camera (30% weight): Used for selfies and video calls

Rationale: Camera quality is a major differentiator in smartphone pricing.


**Feature 3: Display Score**

Formula: display_score = (Screen_Size × 0.3) + ((Resolution_W × Resolution_H) / 1,000,000 × 0.4) + (Refresh_Rate / 10 × 0.3)

Components:
- Screen Size (30%): Physical display area
- Resolution (40%): Pixel density and visual clarity
- Refresh Rate (30%): Display smoothness

Rationale: Display quality is a premium feature in expensive smartphones.


**Feature 4: Battery Efficiency**

Formula: battery_efficiency = Battery_Capacity / Screen_Size

This ratio measures battery capacity relative to screen size, as larger 
screens consume more power.

Rationale: Premium phones often focus on efficiency rather than raw capacity.


**Feature 5: Premium Features Count**

Formula: Count of (5G + NFC + IR_Blaster) where each = 1 if "Yes"

Range: 0 to 3

Rationale: Advanced connectivity features are typically found in expensive phones.


**Feature 6: Brand Premium Score**

Formula: Average rating of all phones from the same brand

This captures brand reputation by calculating the mean customer rating for 
each brand and assigning it to individual phones.

Rationale: Brand perception significantly influences pricing.


Result: Dataset expanded from 32 to 38 features (6 new engineered features).


2.5 CATEGORICAL ENCODING
--------------------------------------------------------------------------------

Machine learning algorithms require numerical inputs, so all categorical 
features were converted to numbers using two encoding strategies:

A) Binary Encoding (for Yes/No features):
   • Features: Dual_Sim, 4G, 5G, Vo5G, NFC, IR_Blaster, memory_card_support
   • Method: "Yes" → 1, "No" → 0
   • Rationale: Simple and interpretable for binary categories

B) Label Encoding (for multi-category features):
   • Features: Processor_Brand, Performance_Tier, brand, os_name, Notch_Type, 
     RAM Tier, Processor_Series, memory_card_size, os_version
   • Method: Assign unique integer to each category
   • Example: Samsung=0, Apple=1, Xiaomi=2, etc.

Code Applied:
    # Binary encoding
    df[feature] = (df[feature] == 'Yes').astype(int)
    
    # Label encoding
    le = LabelEncoder()
    df[col] = le.fit_transform(df[col])

Result: All 38 features converted to numerical format.

2.7 FEATURE SCALING
--------------------------------------------------------------------------------

Feature scaling normalizes all features to similar ranges, which is essential 
for distance-based algorithms (SVM, Logistic Regression) and improves 
convergence in gradient-based optimization.

Method: StandardScaler (Z-score normalization)

Formula: z = (x - μ) / σ

Where:
- x = original value
- μ = mean of the feature
- σ = standard deviation of the feature

Result: All features transformed to have mean ≈ 0 and standard deviation ≈ 1

Important: The scaler was fitted only on training data to prevent data 
leakage, then applied to both training and test sets.

4.2 HYPERPARAMETER TUNING METHODOLOGY
--------------------------------------------------------------------------------

**Method: GridSearchCV with 5-Fold Stratified Cross-Validation**

GridSearchCV performs exhaustive search over specified parameter combinations:
1. Define a grid of hyperparameter values to test
2. For each combination, perform 5-fold cross-validation
3. Calculate average accuracy across all folds
4. Select combination with highest average score

**Cross-Validation Strategy:**
- StratifiedKFold with 5 splits
- Maintains class proportions in each fold (72% non-expensive in each)
- Shuffle enabled for randomization
- random_state=42 for reproducibility

5.1 ENSEMBLE LEARNING METHODS
--------------------------------------------------------------------------------

**Bagging (Bootstrap Aggregating) - Random Forest:**
- Creates multiple models on random subsets of data
- Combines predictions through majority voting
- Reduces variance and overfitting

**Boosting (XGBoost, Gradient Boosting):**
- Builds models sequentially, each correcting previous errors
- Focuses on difficult-to-classify instances
- Reduces bias and improves accuracy

**Benefits Achieved:**
- Ensemble methods outperformed single algorithms (Logistic Regression)
- XGBoost achieved 4% higher accuracy than Logistic Regression


5.2 CROSS-VALIDATION
--------------------------------------------------------------------------------

**5-Fold Stratified Cross-Validation:**
- Divides data into 5 equal parts
- Each part serves as test set once
- Maintains class proportions in each fold

**Benefits:**
- Provides reliable performance estimates
- Reduces overfitting risk
- Identifies optimal hyperparameters robustly

**Implementation:**
    cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
